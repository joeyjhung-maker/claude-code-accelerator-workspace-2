## Git workflow fix: no more `git add -A`

Joey is now running Claude Code and Codex at the same time against the same GitHub repo
(two-machine setup, shared remote). Flagged the risk that a blanket `git add -A` at close-out
could sweep up the other tool's uncommitted work into a Claude commit.

Corrected `daily-git-commit-on-closeout` in memory: Claude now stages and commits only the
specific files it created or touched in its own session, by name — never `git add -A`,
`git add .`, or `git commit -a`. Anything else sitting in `git status` is left for the other
tool to commit itself.

No copy or creative work this session.
